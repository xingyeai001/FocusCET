# FocusCET

把番茄工作法和**四级 / 六级**备考绑在一起的本机学习台。Electron 桌面应用，数据全部存在本地，不联网、不注册。

> 2026-11 由「番茄四六级」改名而来。数据目录随之从 `cet4-pomodoro` 换成 `FocusCET`：
> 新目录还没有 `config.json` 时，启动会把旧目录里的配置和自定义铃声**复制**过来，
> 旧目录原样保留（确认没问题后可以自己删）。只复制、不搬移，改错了也不会丢东西。

## 安装与运行

**装好直接用**：到 [Releases](https://github.com/xingyeai001/FocusCET/releases) 下载
`FocusCET-Setup-0.1.0.exe`，双击安装（安装时可自选目录）。要求 Windows 10 / 11 x64。
这个版本没有做代码签名，首次运行 Windows 会提示「未知发布者」，点「更多信息 → 仍要运行」。

**从源码跑**：

```bash
npm install
npm start            # 开发模式：改代码自动重载
npm run sandbox      # 沙盒模式：数据写临时目录，不碰真实进度
npm run e2e          # 端到端测试：自动操作界面并截图
```

`engine/`（98 MB 离线语音引擎）没有纳入仓库，因为它是第三方资源、体积又大。缺了它应用照样能跑，
只是发音会退回系统 TTS（中文 Windows 上读英文单词效果很差，所以还是建议补上）：

- `engine/piper/` — 从 [rhasspy/piper releases](https://github.com/rhasspy/piper/releases) 取 Windows x64 包，解压后整个目录放进来
- `engine/voices/` — 从 [piper-voices](https://huggingface.co/rhasspy/piper-voices) 取 `en_US-lessac-medium.onnx` 和同名的 `.json`

许可：Piper 为 MIT，espeak-ng 及其数据为 GPLv3，lessac 语音模型为 CC BY 4.0。

## 它和普通番茄钟的区别

普通番茄钟只知道「25 分钟」，不知道你在做什么。这个工具的做法是：**每个题型有它自己的自然时长**。

- 精听短文 25 分钟，正好一个番茄
- 阅读套题 40 分钟，一次做完，中途不许停
- 写作 35 分钟，比一个番茄长一点
- 整卷模考 130 分钟，不用番茄

计时器按任务类型定长度，超过 25 分钟的任务会在整点处轻提示一次，但不打断——因为四六级考的是连续 130 分钟不断线，不是在训练「25 分钟一到就放下」。

## 功能

**外观**
- 深浅两套配色，外加三种系统材质：**亚克力 / 云母 / 云母 Alt**，窗口变半透明，透出桌面壁纸
- 材质要 **Win11 22H2（build 22621）以上**。系统不支持时那几档会直接置灰并写明原因，
  而不是让你点了没反应、或者留下一块"透了桌面却没有毛玻璃"的半透明窗口
- **亚克力点了别处会"掉"**：Windows 把桌面亚克力（`DWMSBT_TRANSIENTWINDOW`）定义为
  瞬态表面材质（弹出层、右键菜单那种），窗口一失去焦点 DWM 就停止绘制，背景退回清晰。
  这是系统规定，不是程序 bug，Electron 也没有开关能关掉它（Electron 自己的 API 文档就写着
  acrylic 对应 "a transient window"）。想要"一直挂着也不变"就用**云母 / 云母 Alt**——
  它们对应 `DWMSBT_MAINWINDOW` / `DWMSBT_TABBEDWINDOW`，是长生存期窗口的材质，失焦照样画
- 材质的明暗跟应用的深浅色走（会同步窗口的暗色标记），所以浅色系统 + 深色应用也不会糊成一片
- 毛玻璃由 Windows 自己画，不用 JS 模拟；代码只管把 html / body / 面板的实色一层层让开
- 顺带一提：材质是 DWM 画在窗口后面的一层，**CDP 截图截不到**（截出来是白的），
  只能靠肉眼看，别拿截图判断效果

**计时**
- 一个番茄只能做一件事，中途放弃即作废，不计入今天的账
- 干扰记录：外部打扰和内部走神都写下来，计时不停
- 铃响自动进入休息，休息时长可调
- 窗口收进托盘后倒计时继续走，托盘提示实时显示剩余时间
- **电脑睡了一觉不会把这段算进番茄**：合盖期间计时暂停推进，醒来自动顺延，账不虚记

**今日安排**
- 按当前阶段自动生成，任务全部来自内置题库
- 阶段按积累量推进：基础期 → 积累期 → 强化期 → 模拟期
- 也可以手动锁定阶段，或加自己的任务

**复习（艾宾浩斯）**
- 词库两套，设置里一键切换：
  - **四级池 4545 词** = 核心 100（手工挑的高频词，带例句）+ 四级全表 4543
  - **六级池 6662 词** = 核心 100 + 六级新增 2118 + 四级全表 4543（基础词兜底）
- 六级池故意把「六级新增词」排在四级基础词前面：六级真正拉开差距的就是那 2118 个词，
  四级那 4500 个是地基，背完增量再回头补底子，性价比更高
- 复习间隔：10 分钟 → 1 天 → 2 天 → 4 天 → 7 天 → 15 天 → 30 天 → 60 天
- 三档评分：忘了回到第一档，模糊退一档，记得进一档
- 键盘：**空格**翻面（新词页是「下一个」），**1 / 2 / 3** 评分 —— 每天几十次点击都在这页
- 新词先看一遍不考，10 分钟后才测
- 每天发 N 个新词（可调到 5–50），发出去的才会成卡
- 支持粘贴导入自己的卡片，格式：`单词 | 释义 | 例句`

**发词顺序：按词频，不是按原表顺序**

原始词表是乱序的（那份词表本身被洗过牌），所以改之前"核心 100 之后下一个学什么"
完全随机 —— 可能今天发 `access`，明天发 `equivalence`，难度和常用度参差不齐，
等于把每天那 10 个名额交给运气。

现在每个词都带一个频次排名（`src/word-freq.json`，来自 Google Web Trillion 语料，
源表 227,031 条，四六级词表覆盖 99.6%），按它排序发牌。

但不是纯按排名 —— 四级词表里排最前的 40 个是 `of / and / a / in / for / on / by`，
这些是小学词，占名额等于浪费时间。所以分三层，层内再按「频次 + 词长」打分：

| 层 | 判定 | 去处 |
|---|---|---|
| 主体词 | 不满足下面两条 | 最前，真正该花时间学的 |
| 基础词 | 排名 ≤ 2000 **且** 不超过 7 个字母（of / page / nature / foot） | 主体词之后兜底 |
| 生僻词 | 词频表里查不到（aviate / impermanency） | 最末 |

首字母大写的专有名词（China / Monday / European / January，共 59 个）一律降到基础层：
认得，但不用背。

为什么要加词长这一刀：纯按频次排，六级池第一个发出去的是 `bug`（3 个字母），
`religion`（8 个字母）排在它后面 —— 可 `bug` 是小学词。英语里短词基本都是
基础词（count / foot / mass / king / heat），词长是"要不要背"的可靠代理。

实测曲线（四级主体段前 N 个的平均频次排名）：

```
前 100 → 735     前 500 → 1910     前 1000 → 2661
前 2000 → 4315   全程 3566 → 11103
```

单调递增，说明确实从常用往生僻走；前 300 个里最生的词排名 3212，
没有出现"生僻长词被词长修正顶到最前面"的情况。

**备考配速（避免「背了两年还没背完」）**
- 填上考试日期，程序倒推：按当前速度到考试能过多少词、差多少、要全过完得每天几个
- 不够就直说不够，不拿一个不可能的数字安慰人
- 「按考试配速」一键把每天新词调到刚好的数，超过 50 就顶到 50（一天发一百个词不是勤奋，是当天下不去手背）

词库来源：[KyleBing/english-vocabulary](https://github.com/KyleBing/english-vocabulary)（BSD-3-Clause）。
四级原表 7508 行去重后 4543；六级原表 5651 行去重后 3991，其中 1873 个四级表里已有，六级独有 2118。
只取"单词 + 释义"：原表没有音标也没有例句。

**发音**：词表没有音标，所以靠语音把词读出来。应用**自带一个离线神经语音引擎**，
不联网、不装系统语音包、不要管理员权限，装好就能点。

为什么不能直接用 `window.speechSynthesis`：Windows 有两套语音库 ——
老的 SAPI5（`HKLM\SOFTWARE\Microsoft\Speech`）和新的 OneCore
（`SOFTWARE\Microsoft\Speech_OneCore`）。Chromium **只枚举 OneCore 那套**，
而中文版 Windows 的 OneCore 里只有 Huihui / Kangkang / Yaoyao 三个中文音。
于是 `getVoices()` 一个英文音都拿不到 —— 实测 Zira 明明注册在 SAPI5 里、磁盘上模型也在，
浏览器就是看不见。用中文音去拼英文是假发音，跟着记反而更糟，所以那种情况下宁可不响。

现在的做法：内置 [Piper](https://github.com/rhasspy/piper)（MIT 许可）+
`en_US-lessac-medium` 模型（22kHz，音质比系统 Zira 更自然）。
音素化用 espeak-ng，合成走 onnxruntime，全程离线。

- 一个词约 0.05 秒合完，但起进程要加载 60MB 模型（约 0.5s），所以**不逐词起进程**，
  而是一批词用 `--json-input` 一次喂进去
- 结果按「词 + 语速」哈希后落盘缓存，第二次点是 0ms
- 打开复习页会把今天这些词**后台预热**，点的时候已经好了
- 语速三档（慢 / 正常 / 快 = length_scale 1.35 / 1.15 / 1.0），默认比正常慢一点，为了听清 -ed / -s

引擎不可用时（比如被安全软件删了）才退回系统语音；系统也没有英文音就给出安装入口：
`装英文语音-右键管理员运行.bat`（右键 → 以管理员身份运行，约 20MB）。

引擎和模型的许可见 `engine/`：Piper 为 MIT，espeak-ng 及其数据为 GPLv3，lessac 语音模型为 CC BY 4.0。

**词池与卡片是分开的。** 六千多张卡全塞进 `config.json` 会变成 1.3MB 以上，
而每次完成番茄都要重写整个文件并留一份备份，磁盘写入会被放大几百倍。
所以词池是只读的文本文件，`cards` 里只放"手上正在学的"这些。实测全新启动时 `config.json` 只有 4.5KB。

**记录**
- 近 7 天专注柱状图
- 遗忘曲线对照图（不复习 vs 按曲线复习）
- 题型时间分布、连续天数、作废记录

**记录的容量：明细留 2000 条，累计数字不封顶**

番茄记录（`sessions`）只保留最近 **2000** 条明细 —— 按每天 10 个番茄算够 200 天，
`config.json` 也稳在 300KB 上下，不会越用越大。界面上的「最近记录」再从这里取最近 20 条。

但「累计番茄 / 累计分钟 / 时间花在哪」是从明细汇总出来的，如果直接裁掉，
**攒了半年的总数会往回退**。所以裁剪前先把被裁掉的那部分折进 `lifetime` 账本，
统计时「账本 + 明细」两边相加（`src/lifetime.js` 统一口径，两边永不重叠）。
账本只装被裁掉的老记录，作废记录不进账本。

老配置文件里没有 `lifetime` 字段也能直接读：补成空账本 + 现有明细，和加字段之前完全一致。
「重新开始 → 清空学习记录」会把账本一起清零。这条逻辑有单测盯着（`node build/selftest.js` 第 9 节）。

**全部记录与删除**

记录页的「最近记录」右上角有「全部记录」，点开是弹层：按月分组列出明细里那 2000 条，
每条右侧有删除按钮。删除**不弹确认框**（每删一条问一次太烦），而是在提示条上给 6 秒撤销窗口。

删一条要同时动两处，漏一处统计就对不上：

| 位置 | 处理 |
|---|---|
| `sessions` | 移出该条 |
| `days[那天的 key]` | 完成记录要减掉 1 个番茄和对应分钟（今日统计、近 7 天、连续天数都看这里） |
| 累计数 | 不用管，每次都由「账本 + 明细」现算 |
| 计划的勾选 | **不回退**：那条记录代表"做过"，删记录不等于把任务打回未做 |

撤销会把整条记录按时间插回原位，并把那天的人数补回去，所以删→撤销后统计与删除前一致。
入参从渲染进程绕回来，所以只认白名单字段并逐项转类型，不让乱数据混进 `config.json`。

已经折进 `lifetime` 账本的老记录不在明细里，弹层看不到、也删不掉 —— 它们只剩累计数字，
删了反而要让累计倒退，没有意义。

**铃声**
- 8 种内置音色，全部现场合成，不占体积、不联网
- 音量 0–100 可调，可设连响 1 / 3 / 6 声
- 支持上传自己的音频（wav / mp3 / ogg / m4a / aac / flac，单个 2MB 以内）
- 不依赖系统通知：开着专注助手也能响
- 窗口收进托盘、切到别的程序时照常响（主进程计时，`backgroundThrottling` 已关）

## 跑起来（开发阶段）

不需要打包，双击就行：

| 文件 | 用途 | 数据落在哪 |
|---|---|---|
| 桌面上的 `FocusCET` 图标 | 平时用这个，双击就开，没有黑窗口 | `%APPDATA%\FocusCET` |
| `双击我-开发模式.bat` | 日常开发，带控制台日志 | `%APPDATA%\FocusCET` |
| `双击我-沙盒测试.bat` | 随便造、随便删，不碰真实进度 | `%TEMP%\focuscet-sandbox` |

桌面快捷方式指向本机的 `node_modules\electron\dist\electron.exe`，参数是项目目录，所以
**挪动项目文件夹或重装依赖后它会失效**，重新生成一次即可：

```bash
env -u ELECTRON_RUN_AS_NODE node_modules/electron/dist/electron.exe build/mkshortcut.js
```

（`build/mkshortcut.js` 走 Electron 自带的 `shell.writeShortcutLink`，不经过 COM——
本机安全策略禁止创建 `WScript.Shell` 这类对象。）

也可以走命令行：

```bash
npm start                  # 开发模式
npm run sandbox            # 沙盒，保留上次的沙盒数据
npm run sandbox:fresh      # 沙盒，每次从一张白纸开始
npm start -- --devtools    # 启动时直接把开发者工具打开
npm start -- --view=review # 启动直接落到复习页
```

开发模式下：

- **F12** 或 **Ctrl+Shift+I** 打开开发者工具
- **Ctrl+R** / **F5** 刷新页面
- 改了 `renderer/` 下的文件 → 窗口自动刷新
- 改了 `main.js` / `preload.js` / `src/` → 应用自动重启
- 关窗口即退出，不会缩进托盘（省得每次去右下角捞）

## 数据在哪

```
%APPDATA%\FocusCET\config.json
%APPDATA%\FocusCET\sounds\     上传的铃声原文件
```

- 每次保存是原子写入（先写临时文件再改名），断电不会写出半截 JSON
- 覆盖前会把上一版备份成 `config.bak.json`
- 读到坏文件时先备份成 `config.json.broken-<时间戳>`，再尽量抢救内容
- 卸载程序不会删这个目录
- 备份 JSON 里只有铃声的**记录**，音频文件本身不进去。换电脑后如果铃声丢了，重新传一次即可（程序会自动把找不到文件的记录清掉，不会留一个点了没反应的选项）

设置里有「导出 / 恢复 / 打开目录」，换电脑前先导出一次。

想从零开始时用「清空学习记录」：番茄、卡片进度、今日安排全清，设置保留；
旁边还有「连设置一起」退回出厂。两个都不会直接抹掉 —— **清空前自动存一份
`重置前备份-<时间>.json`**，点错了用「恢复」就能捡回来。确认框要求亲手打出
「清空」两个字才放行，比「确定 / 取消」难误触得多。

## 自测

```bash
node build/selftest.js     # 纯逻辑：词库解析、阶梯推进、三档评分、阶段判定、计划生成、曲线采样
npm run e2e                # 端到端：真启动 + 真截图 + 真测铃声波形
node build/audiotest.js    # 只验声音：8 种音色逐个量输出峰值
node build/belltest.js     # 只验链路：到点 → 响铃 → 自动进休息
```

`e2e` 里的铃声用例不是"调用了就算过"。它在音频输出链上插一个 `AnalyserNode`，
测真实的波形 RMS，`peak > 0.003` 才算通过。因为"代码被调用"和"人真的听见了"是两回事。

## 代码结构

```
main.js              主进程：计时器状态机、托盘、通知、铃声下发、窗口、IPC
preload.js           contextBridge 暴露的接口
src/store.js         数据持久化（原子写 + 备份 + 抢救）
src/lifetime.js      记录明细裁剪 + 累计账本（唯一会"丢明细"的地方，有单测）
src/schedule.js      艾宾浩斯调度、计划生成、统计（纯逻辑，可单独测）
src/data.js          任务库、阶段定义、词池加载（四级 / 六级两套）+ 词频分层排序
src/word-freq.json   每个词的频次排名（6635 条，build/reorder.js 生成）
src/cet4-words.txt   四级词表 4543 词（只读，按需发牌）
src/cet6-words.txt   六级词表 3991 词（只读；其中 2118 个是四级没有的）
src/tts.js           单词发音：Piper 批量合成 + 缓存 + 预热队列
engine/piper/        离线语音引擎（piper.exe + espeak-ng 数据 + onnxruntime）· 未纳入仓库，见上方说明
engine/voices/       语音模型 en_US-lessac-medium.onnx（63MB）+ 配置 · 未纳入仓库
renderer/bell.js     铃声：8 种内置音色现场合成 + 用户上传音频解码播放
renderer/app.js      界面逻辑
renderer/style.css   样式（深/浅双主题 + 系统材质 .mat 皮肤）
build/FocusCET.ico   快捷方式专用图标（与 icon.ico 同内容，换路径是为了破 Explorer 图标缓存）
build/reicon.js      从 build/icon.png 生成窗口 / 托盘小图标
build/mkshortcut.js  生成桌面快捷方式（走 Electron API，不用 COM）
build/reorder.js     从词频源生成 src/word-freq.json
build/selftest.js    逻辑自测
build/e2e.js         端到端测试（自动截图）
build/audiotest.js   声学测量
build/belltest.js    响铃链路验证
_legacy/             早期单文件原型，不参与运行也不参与打包
```

两个不显眼但关键的设计：

**计时器放在主进程而不是界面里** —— 窗口最小化、切页面、收进托盘时它都得继续走，渲染进程会被节流，靠不住。

**铃声不靠系统通知** —— `new Notification()` 在专注助手开启、免打扰、通知权限被收回时会完全无声。所以自己合成声音并播放，系统通知只当附加的一条文字提示。

**布局是固定 780 单列，不跟窗口宽度变形** —— 今日 / 复习 / 记录 三页都是同一条 780 的居中列，
窗口拉多宽都一样（1707 宽时两侧各空 464）。试过按宽度分三档（`1000px+` 用 880、`1320px+` 换两栏 1140），
也试过铺满整个窗口，两条路都撞墙：拉宽之后列表行「词汇」到右边「12 分钟」之间能空出 700–900px，
行内两端失去联系，看着比两侧留白难受得多。宁可两侧白，也不要一行从左边标题直接跳到右边数字。
设置页是唯一例外：左导航 160 + 内容 852 = 1040，19 个设置行要这个宽度才不至于挤。
`build/e2e.js` 里有一条用例用 CDP 把视口改成 1440×900，守的就是「宽了也不变形」：内容仍是 780、首页单列、复习侧栏不出现。

**滚动区域常留一条滚动条位（`scrollbar-gutter: stable`）** —— 复习页内容不满一屏、没有滚动条，
其他页有；滚动条一出现一消失，内容区宽度就差 10px，居中的 780 列会左右跳一下（看起来像"复习页向右对齐了"）。
常留轨道之后四页的左边界都是 57px，切页不再位移。
